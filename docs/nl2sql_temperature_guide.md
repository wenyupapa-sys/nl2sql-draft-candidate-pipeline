# NL2SQL 打榜温度参数选择指南

> 基于 BIRD 榜单实战经验，覆盖 Qwen3-max 和 Gemini 2.5 系列。

---

## 核心原则

1. **生成要多样性，判断要确定性** — 不同 pipeline 环节用不同温度
2. **只调一个参数** — temperature 和 top_p 不要同时拧
3. **固定 seed 做消融** — 否则无法区分温度效果和随机波动

---

## Qwen3-max

### 参数约束

| 项目 | 值 |
|------|-----|
| 取值范围 | [0, 2) |
| 默认值（非思考） | 0.7 |
| 思考模式最低温度 | ≥ 0.2（greedy decoding 会导致性能退化和无限重复） |
| 默认 seed | 1234 |

### 按 Pipeline 环节

| 环节 | 任务类型 | 思考模式 | Temperature | Top_p | 理由 |
|------|---------|---------|-------------|-------|------|
| Schema Linking | 分类/映射 | 关 | 0.1 | 0.8 | 确定性映射，不需要多样性 |
| SQL 生成（单发） | 生成 | 关 | 0.1–0.2 | 0.8 | 追求语法正确和逻辑稳定 |
| SQL 生成（单发，难题） | 生成 | 开 | 0.3 | 0.95 | 思考模式需要采样空间展开推理链 |
| SQL 生成（多候选采样） | 生成 | 开 | 0.6 | 0.95 | 需要候选间有差异性 |
| Self-Correction | 修复 | 开 | 0.2–0.3 | 0.95 | 少量探索空间，但不能漂移太远 |
| Selector | 判断/排序 | 关 | 0.1 | 0.8 | 纯分类任务，确定性优先 |

### 按题目难度（单发场景）

| 难度 | 思考模式 | Temperature | 说明 |
|------|---------|-------------|------|
| Simple | 关 | 0.1 | 直接映射即可，省 token |
| Moderate | 可选 | 0.2 | 涉及 JOIN/聚合，视复杂度决定 |
| Challenging | 开 | 0.3 | 多表 JOIN、嵌套子查询、脏值匹配 |

## Gemini 2.5 (Flash / Pro)

### 参数约束

| 项目 | 值 |
|------|-----|
| 取值范围 | [0, 2.0] |
| temperature=0 | 完全支持，无退化问题 |
| 思考模式温度 | **锁定为 1.0，不可调** |
| 多样性控制（思考模式） | 通过 `thinking_budget` 控制推理深度 |

### 按 Pipeline 环节

| 环节 | 思考模式 | Temperature | thinking_budget | 理由 |
|------|---------|-------------|----------------|------|
| Schema Linking | 关 | 0 | - | 完全确定性 |
| SQL 生成（单发） | 关 | 0 | - | greedy 最稳 |
| SQL 生成（单发，难题） | 开 | 1.0（锁定） | 8192–16384 | 靠 budget 控制深度 |
| SQL 生成（多候选采样） | 开 | 1.0（锁定） | 4096–8192 | 温度高天然有多样性 |
| Self-Correction | 关 | 0 | - | 修复要精确 |
| Selector | 关 | 0 | - | 判断任务，零温度 |

### Gemini 思考模式注意事项

- 温度锁定 1.0 意味着**每次输出可能不同**
- Challenging 题建议跑 3 次取 majority vote 来稳定结果
- `thinking_budget` 是唯一能调的旋钮：
  - Simple 题：1024（或直接关思考）
  - Moderate 题：4096
  - Challenging 题：8192–16384

## Qwen vs Gemini 对比速查

| 维度 | Qwen3-max | Gemini 2.5 |
|------|-----------|------------|
| temperature=0 可用？ | 非思考可以，思考模式不行 | 非思考可以，思考模式不可调 |
| 思考模式温度控制 | 手动设置（≥0.2） | 锁定 1.0 |
| 推理深度控制 | 通过温度 + max_tokens | 通过 thinking_budget |
| 单发 SQL 推荐温度 | 0.1–0.2 | 0 |
| 多候选推荐温度 | 0.6 | 自带多样性（温度锁定 1.0） |

## 实操 Checklist

- [ ] 先固定 temperature=0.2（Qwen）或 0（Gemini），跑 baseline
- [ ] Pipeline 搭完后，再做温度消融实验
- [ ] 消融时固定 seed，每档至少跑 100 题 sample
- [ ] Prompt 工程（schema linking、column meanings、evidence）优先级远高于温度调参
- [ ] 温度微调预期收益：0.5–1pp；prompt 工程预期收益：5–15pp
